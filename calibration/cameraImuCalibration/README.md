# Camera–IMU autosync calibrator

Offline tool that estimates, for one camera, the rotation **`R_imu→cam`**, the camera↔IMU
**time offset `δ`**, and a constant **gyro bias** from a recorded IMU trace and OFA dense
optical flow over a recorded frame sequence. It deliberately estimates only the rotation and
timing a rolling-shutter de-skew consumes — translation/lever-arm is out of scope.

This tool (all source files in the `calibration/cameraImuCalibration` directory) was built
by Claude Opus 4.8.

## Build

```bash
scons build/bin/cameraImuCalibrationSelfTest   # synthetic round-trip self-test (host-portable)
scons build/bin/cameraImuCalibration           # full tool (Tegra only: drives the OFA)
```

The estimator core is hardware-independent; only the OFA flow front end is Tegra-bound, so
the self-test builds and runs anywhere.

## Self-test (run this first)

```bash
./build/bin/cameraImuCalibrationSelfTest
```

Generates a known ground-truth `R`, `δ`, `bias` and a band-limited all-axis trajectory,
synthesizes a gyro CSV and dense flow, runs the full pipeline, and asserts recovery. Two flow
modes:
- **linear-model** — flow generated by the same linear model the fit inverts, so the
  conventions/signs/timing are validated to numerical precision (R<0.05°, δ<0.1 ms, b<1e-3°/s).
- **projection** — flow generated by exact ray projection through the distortion model;
  exercises the undistortion path at realistic (linearization-limited) accuracy.

It also asserts flip-invariance (the v1 frame-center estimator does not depend on the readout
direction).

## Usage

```bash
# Calibrate every camera in the dataset and write the consolidated result into it:
./build/bin/cameraImuCalibration --dataset /path/to/calibration-data-YYYYMMDD-HHMMSS
```

`--dataset DIR` is a CalibrationWriter directory (`imu.csv` + `cameraN/*.pgm`). All outputs are
written **into that directory** (correlated with the capture; never overwriting production
calibration):

- `imuCalibration-cameraN.yml` / `-plot.csv` — detailed per-camera result + plot data.
- `imuCalibration.yml` — consolidated, production-ready file: a top-level `cameras` sequence
  (index-aligned to `calibration.yml`) carrying `R_imu_to_cam_matrix`, `time_offset_delta_s`,
  and `gyro_bias_deg_s` per camera, plus a `valid` flag. **Move it into place once confirmed.**

| flag | default | meaning |
|------|---------|---------|
| `--calibration PATH` | `calibration.yml` | intrinsics YAML (per-camera `cameras` sequence) |
| `--camera-index N` | all | calibrate only camera N (debug; writes its detail only, not the consolidated file) |
| `--downsample-shift N` | `1` | OFA processing resolution = full ≫ N (0=full, 1=half, 2=quarter) |
| `--stride N` | `4` | subsampling of the flow field |
| `--refine-bias` | off | let the optimizer adjust bias during motion (default: static-segment bias, held fixed) |
| `--rolling-shutter` | off | Row-timed RS-aware fit (see below) |
| `--rs-alpha-reg F` | `1.0` | RS-aware α regularization (0 = pure RS, larger → frame-center) |
| `--max-pairs N` | all | cap frame pairs (quick tests) |

The detailed per-camera YAML restates the conventions in its header. The plot CSV holds the
aligned `|ω_cam|` vs `|ω_imu|` magnitudes and the per-axis `ω_cam` vs `R·(ω_imu−b)` "money plot".

## Capture protocol

The estimator is only as good as the motion and scene.
- **Excite all three rotation axes** — pan, tilt, and roll — with brisk but **smooth**
  motion (avoid jerky angular acceleration, which breaks the frame-center
  approximation). A few seconds each plus mixed motion; ~30–60 s total is plenty.
- **Start with ~2 s static** for bias init.
- **Scene:** textured, well-lit, with **distant and depth-varied content**. Do **not**
  calibrate while facing a near flat wall — near-uniform close depth produces parallax flow
  that can bias the rotation fit. Distant content makes rotational flow dominate.
- **Avoid** dominant moving objects (people walking through frame) and motion blur
  (keep exposure short relative to motion).

## Notes / gotchas

- **Bias defaults to the static segment, held fixed.** The gyro-at-rest bias is stable and
  grounded (observed identical to ~0.01°/s across independent captures). Letting the optimizer
  refine bias during motion (`--refine-bias`) can be more accurate on a clean capture, but on
  parallax/texture-limited ones it absorbs model error into bias (we saw it swing 2–4°/s). So
  refinement is opt-in. If no static segment exists and you don't pass `--refine-bias`, bias is
  zero and the tool warns loudly — record a couple of seconds at rest at the start of the capture.
- **δ is observable only through angular acceleration.** Smooth, low-bandwidth motion leaves
  the time-offset cost surface flat. Capture brisk (but not jerky) motion exciting all three
  axes — see Capture protocol above.
- **Loud diagnostics** The tool warns on: |δ| > one frame period (IMU-timestamp bug),
  bias magnitude > 3°/s, low Stage-1 inlier ratio (parallax / close scene / dynamic content),
  weak Stage-2 correlation (insufficient rotational excitation), high residual RMS, and
  single-axis motion. A low inlier ratio can mean the capture violated protocol (e.g. facing a near
  wall), but at high angular rates it is largely the rolling-shutter signature (see below).
- **`--rolling-shutter` (row-timed mode).** By default we fit one rotation per frame
  pair at the frame-center time. During fast rotation the rows of a frame are exposed across
  the ~9.6 ms readout, so when the angular rate is *changing* the top and bottom rows see
  different ω — a gradient a single-rotation fit cannot represent, which caps the inlier ratio
  near 0.5 regardless of scene. `--rolling-shutter` upgrades Stage 1 to a 6-DoF fit of
  `ω(t) = ω0 + α·τ` (angular velocity plus its intra-frame time-derivative), timing each flow
  vector by its row's exposure (this is where the `flip` flag finally matters). It reports
  `θ = ω0·dt_center`, so Stages 2–6 are unchanged. The self-test's row-timed pass shows it
  recovers ground truth exactly where frame-center is biased ~0.18°. Use it for captures with
  brisk/jerky motion; frame-center is fine for gentle motion.
